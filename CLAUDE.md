## Project Overview

CALA_SafeRL is a Safe Reinforcement Learning framework for autonomous driving in the CARLA simulator. A PPO agent learns to drive while one of three safety shields intercepts and corrects unsafe actions before they reach the simulator.

**Prerequisite**: A CARLA server must be running before any training or evaluation script is launched and the venv in C:\Users\Isaac\Documents\TFG\Shielded-RL\TFG-RL should be activated.

```bash
.\CARLA_0.9.16\CarlaUE4.exe -RenderOffScreen -carla-port=2000   
```

## Commands

### Training

```bash
# Single-run (adaptive shield, performance-based NPC curriculum)
python main_train.py --model_name my_model --shield_type adaptive

# Multi-phase curriculum (4 phases ramp distance + NPC + lr + spawn difficulty)
python train_curriculum.py --base_name myrun
python train_curriculum.py --base_name myrun --start_phase 2   # resume from phase 2
python train_curriculum.py --base_name myrun --dry_run         # preview commands only

# Pre-generate spawn difficulty profile (requires CARLA running)
python profile_spawns.py --map Town04
```

Key `main_train.py` flags:
- `--shield_type`: `none` | `basic` | `adaptive`
- `--curriculum` / `--no-curriculum`: performance-based NPC curriculum (default: on); disabled automatically by `train_curriculum.py` since the outer loop controls difficulty
- `--obs-norm` / `--no-obs-norm`: online observation normalization (default: on)
- `--kl_target 0.08`: per-minibatch hard stop at 1.5× target aborts the rest of training for this update; soft stop on epoch-mean KL > target breaks after the current epoch
- `--update_timestep 2048`: PPO rollout buffer size
- `--minibatch_size 64`: SB3-style minibatching inside each epoch (`2048/64 = 32` Adam steps per epoch × `k_epochs`)
- `--lr 1e-4`: learning rate (cosine annealed)
- `--entropy_coef 0.001` (default), `--entropy_coef_min 0.0`, `--entropy_coef_decay_updates 50`: linear decay of the entropy bonus. Tuned low because Adam normalizes the gradient — the *direction* of the entropy term saturates `log_std` against its cap regardless of magnitude, so the cure is killing the upward pressure before the saturation horizon, not shrinking it.
- `--spawn_point_indices '1,5,42'`: restrict spawning to a CSV subset of map spawn indices (generated by `profile_spawns.py`); omit to randomize over all map spawns

### Evaluation

`main_eval.py` defaults to **headless + deterministic** (the deployed policy) with **frozen obs-normalization**, and seeds each episode `seed + ep` (identical across shields) for reproducible, controlled comparisons.

```bash
# Fast headless eval (no render/dashboard, deterministic mean action):
python main_eval.py --model_name my_model_adaptive_final.pth --episodes 50

# Shield-dependency ablation in ONE command — same scenarios per episode,
# prints a comparison table and (optionally) saves JSON:
python main_eval.py --model_name my_model.pth --shield_type none adaptive --episodes 50 --out ablation.json

# Interactive debugging (CARLA camera + matplotlib dashboard; single shield only):
python main_eval.py --model_name my_model.pth --render --dashboard

# Stochastic policy instead of the deterministic default:
python main_eval.py --model_name my_model.pth --stochastic
```

Key flags: `--shield_type` accepts **multiple** values for ablation; `--render`/`--dashboard` are **opt-in** (off by default — the dashboard's per-step redraw was the speed bottleneck); `--stochastic` opts into sampling; `--seed` sets the base seed; `--out` saves a JSON summary. Outcomes use the **5-way training taxonomy** (success/crash/offroad/stuck/timeout) as distinct categories. Legacy flags `--no_render`/`--no_dashboard`/`--deterministic` are accepted as no-ops (already the default).

Models are saved to `./data/models/`. The eval script looks there first, then falls back to the literal path.

## Architecture

### Wrapper Chain

The environment is built as a stack of `gymnasium.Wrapper` layers. `build_env()` in both `main_train.py` and `main_eval.py` constructs this chain — order matters:

```python
env = CarlaEnv(...)             # base env
env = Shield(env, ...)          # wraps CarlaEnv (may be omitted with --shield_type none)
env = CarlaRewardShaper(env, .) # outermost — agent interacts with this
```

Call flow when agent calls `env.step(action)`:

```
PPOAgent
  ↕ action / shaped obs & reward
CarlaRewardShaper           ← outermost; shapes reward, then passes action inward
  ↕ action / base reward + info
[Shield]                    ← intercepts and may override action before CARLA sees it
  ↕ corrected action / raw obs
CarlaEnv                    ← gymnasium.Env wrapping the CARLA Python API
  ↕ CARLA API
CARLA Simulator
```

Shield type is selected via `--shield_type`.

### Observation Space (739 dims)

Three semantic LIDAR channels (high-mount only) + lane/marking/vehicle/route features.
Constants defined in `CarlaEnv`: `LIDAR_DIM=DYNAMIC_DIM=STATIC_DIM=240`, `LANE_DIM=8`, `LANE_MARKING_DIM=4`, `VEHICLE_DIM=2`, `ROUTE_DIM=5`.

> **Model compatibility**: the previous v3 format used a fourth low-mount LIDAR channel (`obs[720:960]`), giving OBS_DIM=979. That channel was removed as redundant. Models trained with state_dim=979 are **not** compatible with the current state_dim=739.

| Slice | Dims | Source | Description |
|---|---|---|---|
| `obs[0:240]` | 240 | LIDAR alto combinado | Techo z=1.0 m, range 50 m. `min(dynamic, static)`. Normalizado [0,1]: 1=libre, ~0=obstáculo cercano. |
| `obs[240:480]` | 240 | LIDAR alto dinámico | Sólo vehículos + peatones. Canal separado para evitar zigzag por guardarraíles estáticos. |
| `obs[480:720]` | 240 | LIDAR alto estático | Sólo muros, quitamiedos, postes, etc. |
| `obs[720:728]` | 8 | Lane features | `lateral_offset_norm`, `heading_error_norm`, `on_edge_warning`, `lane_width_norm`, `dist_left_edge_norm`, `dist_right_edge_norm`, `lane_change_left`, `road_curvature_norm` |
| `obs[728:732]` | 4 | Lane marking type | `solid_left`, `solid_right`, `dashed_left`, `dashed_right` — binarias; permite distinguir cruces ilegales (sólido) de cambios de carril permitidos (discontinuo). |
| `obs[732:734]` | 2 | Vehicle state | `speed_norm`, `steering` |
| `obs[734:739]` | 5 | Route info | `next_wp_angle_norm` (5 m), `wp_angle_20m_norm` (20 m), `progress_norm`, `speed_limit_norm`, `speed_ratio` |

Clipping: `obs[0:720]` → `[0, 1]`; `obs[720:739]` → `[-1, 1]`.

### Action Space (2 dims, continuous [-1, 1])

- `action[0]` — steering
- `action[1]` — throttle/brake (positive = gas, negative = brake)

### Safety Shields (`src/`)

| Class | File | Description |
|---|---|---|
| `CarlaSafetyShield` | `safety_shield.py` | LIDAR threshold + Waypoint API lane correction |
| `CarlaAdaptiveHorizonShield` | `Adaptative_Shield/adaptive_horizon_shield.py` | Same but with 3-level risk (safe/warning/critical) and BicycleModel trajectory prediction |

Both shields expose `get_statistics()` / `reset_statistics()` so `main_train.py` can log semantic intervention breakdowns per episode.

`BicycleModel` (`Adaptative_Shield/BicycleModel.py`) predicts vehicle trajectory N steps ahead using kinematic bicycle equations, calibrated for CARLA's Tesla Model 3 (wheelbase 2.87 m, dt=0.05 s).

**Anti-deadlock recovery** (`CarlaAdaptiveHorizonShield`): the emergency action is brake-only, so a car parked with a heading error gets every forward attempt projected as "will leave lane" → braked → heading never corrects → `stuck` (the dominant residual failure once the `log_std` freeze was fixed — stuck episodes ran ~63% parked / ~70% shielded / ~220 static interventions with NPCs >790 m away, i.e. a deadlock, not traffic). When the car has been stalled for `STALL_PATIENCE` steps (with hysteresis up to `STALL_RECOVERY_EXIT_KMH` so it doesn't oscillate) **and** the situation is provably safe (front clear, no pedestrian, `min_edge ≥ EDGE_GUARD_MIN_NORM`, lateral not critical), the emergency throttle flips from a micro-brake to `STALL_RECOVERY_THROTTLE` (gentle forward creep) while keeping the steer-to-lane correction. The frontal/pedestrian/edge/critical-lateral brake branches take priority and are unchanged — proactive hazard braking is not weakened.

### PPO Agent (`src/PPO/`)

- `ActorCritic` — LIDAR encoder compresses obs[0:720] from 720→64 dims; 64+19 vector features feed a shared-trunk MLP (2×256, Tanh). Separate actor head (mean + `log_std` parameter) and critic head. Policy is TanhNormal with numerically stable log-prob using the log-det of the tanh Jacobian. `LOG_STD` is bounded to `[-3.0, -1.2]` (σ∈[0.05, 0.30]) via a **tanh-squashed parameterization**: `log_std = mid + span·tanh(actor_log_std)` (mid=−2.1, span=0.9; see `ActorCritic.log_std()`), with the raw `actor_log_std` parameter initialized via `atanh` so the **effective** log_std starts at `LOG_STD_INIT=−1.5` (σ≈0.223). Tanh squashing replaced the earlier straight-through clamp because it gives a smooth, naturally vanishing gradient near the bounds — the clamp had **zero gradient beyond the cap**, so once the entropy bonus pushed `actor_log_std` past the old `LOG_STD_MAX=−0.7` the effective σ stayed **frozen at 0.497** for the rest of training even after `entropy_coef→0`; that pinned-high variance drove the Phase-1 turtle/stuck collapse (run `TestFinalHope1_p1`: `sat_frac=1.0`, `entropy=1.438` from update ~27 onward). The lowered ceiling (σ_max 0.497→0.30) caps exploration noise and the smooth gradient lets σ **anneal down** as the policy converges. Actor head initialized orthogonal (gain=0.1) with throttle bias +0.8 (cold-start fix). The `LOG_STD` history and tuning rationale are documented inline in `ActorCritic.py`.
- `PPOAgent` — **Shield mask**: policy loss and entropy are computed only over unshielded steps (`shield_mask[t]=0`); critic trains on all steps. GAE advantage estimation, clipped surrogate loss, value clipping. **Minibatching (SB3-style)**: each epoch reshuffles the rollout into minibatches of `minibatch_size` (default 64), giving ~32× more Adam steps per update than full-batch and finer-grained KL stopping; each minibatch recomputes its own `unshielded_count` for safety on densely-shielded segments. **KL early-stop**: per-minibatch hard stop at 1.5·target aborts the rest of training for this update; soft stop on epoch-mean KL > target breaks after the current epoch. Cosine LR schedule, online obs normalization via `RunningMeanStd`, and **SB3-style reward scaling**: rewards are divided by the running std of a discounted-return accumulator `R̄_t = γ·R̄_{t-1} + r_t` (reset on `done`; scale-only, no mean subtraction; accumulator persisted across `update()` calls so episodes spanning a rollout boundary stay continuous). Rewards and V(s) live in the same normalized space so GAE stays consistent and critic loss does not blow up as returns grow.
- Per-update telemetry (logged by `main_train.py`): `policy_loss`, `value_loss`, `entropy`, `approx_kl`, `grad_norm`, `epochs_run`, `epochs_rejected`, `n_updates` (total Adam steps), `log_std_steering_raw` / `log_std_throttle_raw` (the effective post-tanh log_std actually used by the policy — diagnose saturation), `log_std_saturated_fraction` (fraction of dims within 0.01 of `LOG_STD_MAX` *or* `LOG_STD_MIN`), `entropy_coef_current`, `shielded_fraction`, `mean_shield_alpha`.
- Checkpoint format v3: `{'policy': state_dict, 'obs_normalizer': rms_state, 'ret_rms': rms_state, 'returns_acc': ndarray}`. v2 checkpoints (without `ret_rms`/`returns_acc`) still load — those fields rebuild online.

### Reward Shaping (`src/reward_shaper.py`)

`CarlaRewardShaper` adds dense components on top of `CarlaEnv`'s sparse base reward:
- Speed bonus (Gaussian around target speed, curvature-adjusted)
- Lane centering & heading alignment (gated by minimum speed, multiplicative `lane_keep_mult`)
- Smoothness penalty (steering delta)
- Alive bonus
- Edge proximity penalty (quadratic)
- Progress milestone bonus (every 25 m)
- Idle penalty after a per-episode grace period (prevents shield-induced stalling)
- Solid-line invasion penalty: **flat** `−SOLID_INVASION_PENALTY` (default 2.5) per crossing, **capped at `SOLID_INVASION_EVENT_CAP=6` events per episode** (hard cap = −15.0). Replaces the earlier geometric decay (`5.0·0.5^k`, asymptote −10.0) which diluted marginal cost so fast that an agent committed off-lane had no gradient to return. Raw event count is still exposed as `info["solid_invasion_event"]`.

Lane change transitions (`lane_change_permitted=True` AND `|lateral_offset_norm| > 0.5`) suppress invasion, edge, and drift penalties to avoid penalizing intentional lane changes.

### Curriculum

There are **two independent curriculum mechanisms** that can be combined or used separately.

#### 1. Performance-based NPC ramp — `CurriculumManager` (`src/curriculumManager.py`)

Runs inside a single `main_train.py` session. Divides `[0, max_npc]` into 5 stages (0%, 25%, 50%, 75%, 100% NPCs), e.g. `max_npc=40` → `[0, 10, 20, 30, 40]`. Controlled by rolling 100-episode sliding windows of `crash_rate`, `offroad_rate`, and `avg_reward`. NPCs are updated in-place — no CARLA reconnection for stage changes.

Advance thresholds (evaluated after `min_eps_per_stage=100` episodes in the current stage):
1. **Stage 0** — `offroad_rate < 20%` AND `avg_reward > 0`
2. **Stage 1** — `crash_rate < 25%` AND `offroad_rate < 15%`
3. **Stage 2** — `crash_rate < 15%`
4. **Stage 3** — `crash_rate < 10%`

**Rollback** (loose thresholds — tolerates normal variance): if the agent collapses for `rollback_patience=50` consecutive episodes (counter increments on collapse, decrements by 1 otherwise), the stage drops by one.

#### 2. Multi-phase outer curriculum — `train_curriculum.py`

Orchestrates 4 sequential `main_train.py` runs (each 2000 episodes by default, ~2–3 h). Each phase passes `--no-curriculum` so `CurriculumManager` is disabled — the outer loop controls all difficulty axes:

| Phase | success\_distance | num\_npc | lr   | entropy\_coef | spawn\_tier |
|-------|-------------------|----------|------|---------------|-------------|
| 1     | 100 m             | 0        | 1e-4 | 0.001         | easy        |
| 2     | 150 m             | 10       | 5e-5 | 0.0           | easy+medium |
| 3     | 200 m             | 20       | 2e-5 | 0.0           | all         |
| 4     | 250 m             | 40       | 1e-5 | 0.0           | all         |

Each phase warm-starts from the previous phase's `_final.pth`. Models are saved as `./data/models/{base_name}_p{i}_adaptive_final.pth`.

**Spawn difficulty profiling** (`profile_spawns.py`): walks each map spawn point `--forward_dist` metres along waypoints, accumulates absolute curvature, and classifies each point as `easy` (<15°, wide lane), `medium` (<60°), or `hard` (≥60°). Output saved to `spawn_profiles/<map>.json` and consumed by `train_curriculum.py` via `resolve_spawn_indices()`. If the profile is absent, all phases fall back to random spawn over all map points.

```bash
python profile_spawns.py --map Town04          # generate profile (CARLA required)
python train_curriculum.py --base_name myrun   # run all 4 phases
```

## Key Conventions

- **Synchronous mode** (`fixed_delta_seconds=0.05`, 20 Hz) is required for reproducibility; never disable it.
- **Training seed** defaults to 42; evaluation uses seed 100 to prevent data leakage.
- `info["executed_action"]` from the shield layer contains the action actually sent to CARLA (may differ from the agent's proposed action). `main_train.py` stores the executed action in the replay buffer and re-evaluates its log probability to correctly attribute credit.
- Recommended map for benchmarking: **Town04** (highway loop). Town01–03 for urban, Town05 for max difficulty.

## CARLA Sensor Rules

Rules that apply whenever adding or modifying sensor code. Violations cause silent
data corruption or crashes that are hard to reproduce.

- **Client-server architecture**: the CARLA server is a C++/Unreal Engine 4 process;
  the Python script is the client. They communicate over a TCP socket. Never assume
  the server and client share memory.

- **Semantic LIDAR buffer format**: `sensor.lidar.ray_cast_semantic` produces
  **24 bytes per point** (6 fields: `x, y, z, cos_inc_angle` as `float32` + `object_idx,
  object_tag` as `uint32`). Always decode with a structured dtype — never with
  `dtype=np.float32` (which would give 4 bytes/field × 6 fields = wrong field mapping)
  and never with `reshape(-1, 4)` (would silently drop `object_idx` and `object_tag`).
  Correct pattern:
  ```python
  _DTYPE = np.dtype([("x", np.float32), ("y", np.float32), ("z", np.float32),
                     ("cos_inc_angle", np.float32), ("object_idx", np.uint32),
                     ("object_tag", np.uint32)])
  raw = np.frombuffer(measurement.raw_data, dtype=_DTYPE)
  ```

- **Sensor attachment**: always pass `attachment_type=carla.AttachmentType.Rigid`
  when spawning sensors. `SpringArm` introduces damped lag that desynchronises the
  sensor frame from the vehicle pose in synchronous mode.

- **Coordinate system**: CARLA uses a **Left-Handed** system (Unreal Engine convention:
  X=forward, Y=right, Z=up). When passing point-cloud data to any Right-Handed library
  (numpy geometry, Open3D, ROS, etc.) negate the Y axis: `y_rh = -y_lh`.
  The existing angle convention in `SemanticLidarProcessor` already applies this:
  `angle = atan2(-y, x)`.

- **Radar angles**: `carla.RadarDetection` fields `altitude` and `azimuth` are already
  in **radians**. Pass them directly to `math.cos` / `math.sin`; do not multiply by
  `math.pi / 180` first.

- **Sensor cleanup order**: always call `sensor.stop()` before `sensor.destroy()`.
  Destroying without stopping can fire one last callback on a partially-destroyed
  object and raise a `RuntimeError`. Pattern used throughout this codebase:
  ```python
  if sensor.is_alive:
      sensor.stop()
      sensor.destroy()
  ```

- **Linting**: run `ruff check . && ruff format .` after every code change before
  committing.
